# متابعة المرحلة هـ — تسميات وإمكانية وصول

نقطة البداية: `a231cd273b1e39e0206920af861dbd7621445e2c`. هذه دفعة تحقق وإصلاح للتسميات، وليست اعتماداً نهائياً لإمكانية الوصول أو للإطلاق.

## ما ثبت وأُصلح

فحص axe-core4.10.3 الأول رصد خمسة حقول دون اسم واضح: نوع التحكم للاعبين، الصعوبة، اسم الضيف ومهنته. رُبطت التسميات بالحقول، وأضيفت أسماء مستقلة للاعبين الثمانية وأزرار حذفهم واختيار صورهم. رُبطت أيضاً تسميات الدعوة والرد ووضع الجهاز المشترك.

عولج تحذيران يحتاجان مراجعة لدلالاتARIA: رزم البطاقات وخيارات القرار أصبحا مجموعتين مسمّاتين بدور`group`. شريط تقدم الخروج يعرض الآن الحدين والقيمة ووصف الدخل الحالي لقارئ الشاشة؛ لا يعتمد على عرض لون الشريط وحده.

لم تتغير القواعد أو البيانات المالية أو الحفظv10 أو بروتوكول2 أو الأصول الرسومية. إصدار التخزين`darb-accessibility-v18` يضمن وصول تعديلات العرض إلى النسخة دون اتصال.

## الأدلة

- [قبل الإصلاح](before.json): تسع حالات، وخمسة حقول مخالفة في ثلاث حالات.
- [بعد الإصلاح](after.json):12 حالة دون مخالفات آلية مكتشفة في نطاق WCAG2.0/2.1 A/AA المختار. تشمل البداية، وإعداد لاعبين وثمانية، والجلسة والمراجعة، واللعب والمال، واختيار اللاعبين والسؤال، والانضمام والدعوة ورمزها. توجد تأكيدات مستقلة لأسماء حقول اللاعبين الثمانية وأزرار حذفهم.
- [المفاتيح والنوافذ](focus-check.json): نجاح عشر حالات لعب، وحبس/استعادة التركيز، وخلفية غير تفاعلية، وعدم إغلاق القرار الإلزامي بـEscape، ومنع التأكيد المتكرر، والاستعراض دون تعديل اللعب، والكاميرا والتدوير المحاكى.
- [ترقيةv17→v18](upgrade-check.json): حفظ الأسماء والمهن والنقد وإعادة فتح المباراة بعد إيقاف الخادم ناجحة.
- [إصدار أداة الفحص ومصدرها وبصمتها](audit-engine.json). مكتبةaxe أداة تطوير محلية فقط، ولا تدخل تشغيل اللعبة أو تنزيلها أو عامل الخدمة.

## ما لم يُحسم

بقيت31 ملاحظة آلية تحتاج مراجعة للتباين، عبر الحالات المختبرة؛ كثير منها تكرار لنفس العنصر. أسبابها رسومات وخلفيات وتراكب أو رموز قصيرة لا يستطيع المحلل حسابها. التفاصيل والمواضع محفوظة في`incomplete` داخل التقرير، **وليست حالات ناجحة ولا إثباتاً لمخالفة فعلية**. لم تُغيّر الألوان بالتخمين.

يلزم فحص يدوي للتباين فوق الرسوم، وقارئ شاشة فعلي مثلVoiceOver/TalkBack، وSafari وأجهزة فعلية. لا يغطي هذا الفحص جميع أنواع البطاقات أو الحالات أو متطلباتWCAG2.2، ولا يثبت اكتمالWCAG AA. اختبارات العائلات والشبكة الفعلية ما زالت كما هي في [تقرير المرحلة هـ](../phase-e/README.md)؛ لم تُتجاوز سياسةUDP أو`file://`، ولم ينفذ نشر موقع.

## إعادة الفحص

شغّل خادم المستودع علىlocalhost:8000. للحصول على مكتبة الاختبار المثبتة الإصدار خارج المستودع:

```sh
curl -fsSL https://registry.npmjs.org/axe-core/-/axe-core-4.10.3.tgz -o /tmp/darb-axe.tgz
tar -xzf /tmp/darb-axe.tgz -C /tmp package/axe.min.js
python3 tools/verify_accessibility.py --axe /tmp/package/axe.min.js --output /tmp/darb-accessibility.json --require-clean
python3 tools/verify_play_layout.py --artifacts /tmp/darb-accessibility-layout
python3 tools/verify_upgrade.py --previous-ref a231cd2
```

`--require-clean` يفشل عند وجود مخالفة آلية، ولا يحوّل الملاحظات اليدوية إلى اجتياز. إنتاج رمز الدعوة في الاختبار لا يعني نجاح اتصالWebRTC أو إرسال رسالة إلى شخص.
