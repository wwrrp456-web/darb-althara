# المرحلة ج — مساحة اللعب والكاميرا والتجمعات والنوافذ

**الحالة:** نُفذت الأسس التقنية على التطبيق الفعلي، بعد رد صاحب المشروع «ممتاز اكمل» على سؤال اعتماد تخطيط الجوال والتابلت. اختيار الشعار ١ واعتماد التخطيط محسومان؛ لا حاجة إلى طلبهما مجدداً. نقطة البداية `d9b7febe2799809dd59a67989d63632823c6fa09` على `main`، دون تغييرات محلية.

هذه المرحلة تطبق الأساس الوظيفي للتخطيط المعتمد، وليست إكمالاً للهوية والتجربة أو للنهايات والنمطين. تعميم الشعار والهوية والإرشاد يأتي في د، والنهايات والنمطان والتوازن في هـ. لم تُضف أرقام مالية أو قواعد أو صيغة حفظ أو بروتوكول شبكة جديد.

أجريت مقارنة حرفية مع المرجع على قسم `const PROFS` حتى بداية أوصاف الاستعراض، الذي يحتوي التعريفات والقواعد والمحرك ومساعدات الحفظ؛ لم يتغير، وSHA محفوظ في الدليل. تعديلات `index.html` الأخرى تخص العرض والنوافذ والتخطيط ونسخ ملفات العرض. لم يتغير مفتاح الحفظ أو `G.v` أو أرقام القواعد. اختبار الترقية لا يعني فحص كل حالة حفظ تاريخية، لكنه يتحقق من النسخة المباشرة السابقة وفتح المباراة بعد انقطاع الأصل.

تعديل اختبار الكاميرا مقصود: لم يعد يشترط حركة غير ضرورية للكاميرا حين تبقى القطعة ظاهرة في وضع الملاءمة. يتحقق من بقائها داخل المشهد، واختبار آخر يثبت استئناف المتابعة في الاقتراب عند الحاجة. يشترط اختبار الاستعراض 48px بدلاً من 44، ويستخدم نقر DOM لإعادة رسم fixtures عند تغيير حالة مصطنعة، لأن شريط اللاعبين القديم لم يعد واجهة الجوال. مسار المستخدم البديل «اللاعبون ← الشخص ← اعرض لوحته» مختبر في الأداة الجديدة. لم تُلغ أي مقارنة مالية أو تأكيد للقراءة فقط لتمرير الفحوص.

## قياس الأداء قبل وبعد

المصدر نفسه `tools/measure_tabletop.py`: ثلاث ثوان تقريباً من رصد rAF مع سحب وعجلة وأخذ مقاييس CDP، إبطاء CPU أربع مرات، Chromium 154، كثافة صورة 1، بلا اختبارات متصفح متزامنة. «قبل» من نسخة Git أرشيفية مؤقتة للمرجع `d9b7feb` خارج المستودع، وليست worktree أو فرعاً بديلاً. «بعد» من التطبيق المعدل. ملفات الأصول الأصلية لم تتغير.

| المقاس | FPS قبل | FPS نهائي | P95 قبل / بعد | عناصر اللوحة قبل / بعد |
| --- | ---: | ---: | --- | --- |
| 390×844 | 58.35 | 59.01 | 16.8 / 16.8ms | 323 / 324 |
| 1180×820 | 55.67 | 53.37 | 33.3 / 33.3ms | 323 / 324 |

[القياس السابق](performance-before.json) · [القياس النهائي](performance-after.json) · [قياس وسيط قبل إزالة المدينة](performance-initial-after.json) · [بعد إزالة المدينة وقبل تنقيح أسماء الخانات](performance-after-city-removal.json).

القياس الوسيط سجل 50.06 FPS على التابلت. بعد إزالة الطبقة الزخرفية تغير الكود وأعيد القياس. ثم صحح ظهور أسماء الخانات بحسب حجمها المعروض بدلاً من عرضها المنطقي الثابت، وكبر النص عند الاقتراب، وأعيد القياس على المصدر النهائي. كل العينات محفوظة، ولم ننتقِ أفضل تكرار للكود نفسه. وقت مهام الخيط الرئيسي النهائي للتابلت 3097.88ms مقابل 2293.8ms قبل التعديل، بينما وقت السكربت 177.88ms مقابل 175.66ms؛ لذلك لا نصف كل مقاييس العمل بأنها تحسنت. الهدف ≥50 FPS تحقق في السيناريو النهائي، لكن عينة قصيرة ومحاكاة CPU لا تثبت سلاسة هاتف فعلي أو متعة اللعب.

## ملكية الكود وإعادة الفحص

- `styles/play-layout.css`: التخطيط المتجاوب، صفوف الأوامر والتنبيه والمقاسات وأشكال النوافذ؛ لا اقتطاعات ثابتة من ارتفاع الشاشة.
- `scripts/play-layout.js`: واجهة عرض صغيرة تستقبل قيماً محسوبة، وقياس visualViewport وإدارة النوافذ؛ لا قراءة أو كتابة مباشرة لحالة المحرك أو التخزين.
- `styles/tabletop.css` و`scripts/board-camera.js`: أبعاد منطقية موحدة وملاءمة/سحب/تقريب/متابعة، دون ربط حجم الخانة بقواعدها.
- `scripts/tabletop.js`: عقد القطع الدائمة والتجمع المرئي، دون تغيير الحركة المنطقية أو المواقع المحفوظة.
- `index.html`: نقل نموذج العرض إلى المكونات الجديدة، مع بقاء حساباته وقواعده الحالية.
- `sw.js`: نسخة عرض متسقة v15 مع ملفات CSS/JS الجديدة؛ لا حذف للمباراة المحفوظة.

من جذر المستودع، بعد تشغيل خادم Python على المنفذ 8000:

```sh
python3 tools/verify_play_layout.py
python3 tools/verify_identity.py
python3 tools/run_presentation_checks.py camera --artifacts /tmp/darb-camera
python3 tools/run_presentation_checks.py tabletop --artifacts /tmp/darb-tabletop
python3 tools/run_presentation_checks.py inspection --artifacts /tmp/darb-inspection
python3 tools/run_presentation_checks.py cards --artifacts /tmp/darb-cards
python3 tools/verify_upgrade.py --previous-ref d9b7feb
python3 tools/measure_tabletop.py --output /tmp/darb-performance.json
```

الأدوات الأربع القديمة تكتب صوراً في `brand` عند تشغيلها مباشرة. أداة `run_presentation_checks.py` تغير وجهة الصور فقط وتحافظ على assertions وحالة الخروج. لا تشغّل فحوص متصفح أخرى أثناء القياس النهائي. أُعيدت صور النوافذ بعد انتظار حركة ظهورها كي لا تصبح صوراً انتقالية مضللة.

## ما بقي وحدود التسليم

- المرحلة د: تعميم الشعار ١ والهوية المعتمدة والبطاقات والإرشاد والحركة والصوت. بقي شعار التطبيق السابق في هذه الدفعة عمداً لأن هذه مرحلة الأساس التقني.
- المرحلة هـ: النمطان والنهايات الثلاث ومزامنة المضيف والضيف وتوافقهما واختبارات الاستخدام والتوازن والإطلاق؛ لا تُنسخ بيانات النموذج الثابتة إلى المحرك.
- لم تجر اختبارات هاتف فعلي أو Safari أو قارئ شاشة فعلي أو عائلات أو اتصال بعيد بجهازين. الدوران هنا تغيير أبعاد المتصفح، وليس قياس مفصل لمساحات الأمان ولوحة مفاتيح iOS/Android.
- `file://` لم يعاد اختباره أو تجاوز الحظر السابق؛ لا يوصف بأنه ناجح. بقيت الأصول والخطوط محلية دون إضافة تبعية خارجية لازمة للتشغيل.
- لم تُستدع عملية نشر موقع أو تعديل GitHub Pages. نجاح commit أو الرفع لا يثبت نشر الموقع تلقائياً من منصة الاستضافة.
