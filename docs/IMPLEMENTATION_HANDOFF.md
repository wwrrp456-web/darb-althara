- **التحقق الناجح:** فحص الهوية الوظيفي (مباراة ورمية وحفظ واستعادة وعمل دون اتصال)، وفحص الكاميرا والسحب واللمس والمفاتيح والاستعراض للقراءة فقط، ورصد عشر حالات للاعبين وثمانية على المقاسات الخمسة. لا أخطاء JavaScript أو HTTP في الرصد. نجاح أدوات الرصد لا يعني اجتياز معايير التصميم الجديدة.
- **لم يختبر:** مباراة عائلية مكتملة وتوازنها ومدتها، هواتف فعلية وSafari وقارئ شاشة وتباين شامل، اتصال مضيف/ضيف، ترحيل كامل، النهايات المخططة، FPS جديد، و`file://`. الصور تحاكي الأبعاد، ولا تثبت السلاسة على هاتف فعلي. حالات الثمانية: محليان وستة منافسين آليين؛ المسار السريع fixture مؤقت فقط.
- **المشكلات المتبقية:** A01–A06 مفتوحة؛ لا توجد ادعاءات بإصلاحها. راجع حدود كل دليل في التقرير قبل التنفيذ.

## التكليف الذي بدأت به المرحلة ب (مرجع)

المرحلة **ب: التصميم والاعتماد** من [الخطة المعتمدة](GAME_DESIGN_UPGRADE_PLAN.md): ثلاثة مقترحات شعار تشمل الرمز والاسم العربي المخصص، واختبار 32px ومواضع الاستخدام، ونموذج تفاعلي للجوال والتابلت يغطي البداية والقرار والنهاية وتزاحم ثماني قطع. اعرض المخرجات على صاحب المشروع لاعتماد الشعار والنموذج قبل التعميم.

لا تقفز إلى إصلاحات المرحلة ج أو تغيير القواعد والأرقام والحفظ أو بروتوكول الشبكة ضمن مهمة التصميم. استخدم أصول استكشاف منفصلة عن أصول التطبيق، ولا تستبدل الشعار الحالي أو تحدث عامل الخدمة قبل التكليف بالتطبيق. ابدأ بالخطة وهذا الملخص والتقرير، ولا تعد قراءة المحادثة كلها. `docs/CODEX_TASKS.md` مرجع أقدم للفن والأداء، وليس أمراً بتشغيل مراحله تلقائياً.
